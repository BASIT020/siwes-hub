# SIWES Hub - Database Directory

Everything under this folder is **generated, writable data** - the application
source never lives here, and the server (or you) must be able to write to it.

```
database/
  data/
    db.sqlite3        the application database (created by START_APP.bat)
  server.log          server console output (created by START_APP.bat)
  secret_key.txt      local session-signing key (auto-generated by settings)
  schema.sql          full SQLite schema generated from the Django migrations
  MIGRATIONS.md       list of every applied migration, grouped by app
```

## First start on an empty database

The launcher (`deployment\START_APP.bat`) applies every migration, then calls
`python manage.py bootstrap_admin`. On a fresh database that command asks once
for an administrator username, email and password (the password is typed in
hidden and stored only as a hash). After that, students and supervisors create
their own accounts on the registration page - no sample users are created
automatically.

## Resetting the data

1. Double-click `deployment\STOP_APP.bat` (or close the server window).
2. Delete `database\data\db.sqlite3` (and optionally `secret_key.txt`).
3. Double-click `deployment\START_APP.bat` again - migrations are re-applied
   and the launcher asks for a new first administrator.

## Backing up

Copy `database\data\db.sqlite3` to a safe location while the server is stopped.
Restore by copying the file back.

## Schema

`schema.sql` documents the structure SQLite ends up with after all migrations
(generated by `tools/generate_docs.py` from `backend/*/migrations/`). It is for
reference only - the project never applies it by hand; Django migrations own
the schema.

## Note

The SQLite file is a single-computer file database. Two people cannot share one
database over a network share; each demonstrator should run their own copy of
the portable package.
